# Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| **ABAC Policies / Policy-Matched-Columns sheets are empty** (tags populate fine) | `source_warehouse_id` not set — classic job-cluster Spark cannot read `information_schema.abac_policy_definitions` | Set `source_warehouse_id` to a SQL warehouse on the workspace that owns the objects (required in airgap too). The inventory log prints a WARNING when it's missing. |
| **`CREATE MANAGED STORAGE` denied on catalog create** (`User does not have CREATE MANAGED STORAGE on External Location '…'`), then a cascade of `NO_SUCH_CATALOG` failures | An older build applied the bundle's `OWNER TO <source-owner>` grant right after creating each external location, transferring it away **before** the catalog was created, so the run principal lost `CREATE MANAGED STORAGE` | **Fixed:** the import now defers all `ALTER … OWNER TO` transfers to a final phase (after every object is created and governed), so the run principal keeps `CREATE MANAGED STORAGE`/`CREATE …` throughout. If you hit this on an older build, grant it back — `GRANT CREATE MANAGED STORAGE ON EXTERNAL LOCATION <el> TO \`<principal>\`` (metastore admin) — then re-run. |
| `Metastore storage root URL does not exist` on catalog create | Target metastore has no default storage; catalog needs `MANAGED LOCATION` | Provide storage + mapping file (§ manual-actions §2–3), or pre-create the catalog and set `create_catalogs=false`. |
| `NO_SUCH_STORAGE_CREDENTIAL_EXCEPTION` on external location | Source-named credential doesn't exist on target | Provide `target_credential` in the mapping, or if the target external location already covers the path set `create_storage_credentials=false` + `create_external_locations=false`. |
| `EXTERNAL_LOCATION_MISSING` (MANUAL_ACTION_REQUIRED) on an external table/volume, or a schema with a configured location | Replicating into an existing catalog (existing-catalog mode) but the object's target `LOCATION` has no covering external location on target, or an external table/volume has no row in `object_locations_path` | Add a row to the object-locations CSV (`schema,volume,,location` / `schema,,table,location` / `schema,,,location`) whose path is covered by an **existing** external location, and ensure the run principal has `CREATE MANAGED STORAGE` / `CREATE EXTERNAL …` on that EL. Managed tables/views need nothing. |
| `PERMISSION_DENIED: User does not have CREATE SCHEMA on Catalog '…'` replicating into an existing catalog | The run principal (e.g. a `run_as_spn`) does not own the pre-existing target catalog and lacks `CREATE SCHEMA` | `GRANT USE CATALOG, CREATE SCHEMA ON CATALOG <catalog> TO \`<principal>\`` as the catalog owner (or run the import as the owner). |
| `GOVERNANCE_PREREQ_MISSING` on tags/ABAC | Governed-tag **definition** or a referenced mask/filter **function** missing on target | Create the account-level tag definition (§ manual-actions §4); ensure functions imported (`create_functions=true`). |
| `ROW_COLUMN_ACCESS_POLICIES_NOT_SUPPORTED_ON_ASSIGNED_CLUSTERS` | Masks/row filters on a single-user cluster | Use Standard (USER_ISOLATION) or serverless compute. |
| `COLUMN_MASKS_FEATURE_NOT_SUPPORTED.CHECK_CONSTRAINT` at source read | UC rejects masks on CHECK-constraint tables | Source data model issue; not fixable by migration — remove the constraint or the mask at source. |
| `SCHEMA_NOT_FOUND` on table create (only in a stateless SQL harness) | `USE CATALOG/SCHEMA` didn't persist across calls | Not an issue in notebooks (`spark.sql` is session-stateful); the utility qualifies names fully. |
| `PARSE_SYNTAX_ERROR` replaying captured DDL | Collation / delta.* property / inline policy in `SHOW CREATE` | Handled by the replay sanitizers; if it recurs, capture the DDL and extend `rewrite.py`. |
| Import shows `MANUAL_ACTION_REQUIRED` for a storage credential | Secrets are never exported | Recreate the credential by hand (§ manual-actions §5). |
| A view is `PENDING` | Referenced object not present yet | Re-run Import (incremental) after the dependency exists. |
